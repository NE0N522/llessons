# Код по полочкам — курс HTML/CSS и кабинеты класса

Русскоязычный статический курс с кабинетами учителя и учеников. Учитель ведёт классы, выдаёт индивидуальные учётные записи, публикует задания и проверяет отправленные HTML/CSS работы. Ученики сохраняют черновики, отправляют версии, видят оценки и историю обучения.

## Требования

- Node.js 20 или новее.
- Интернет нужен только для первоначальной установки npm-зависимостей и подключения к удалённой базе в production.
- Локальный режим использует PGlite — PostgreSQL в WebAssembly. База сохраняется в `data/pglite/`.
- Production требует внешнюю базу PostgreSQL и переменные `DATABASE_URL` и `SESSION_SECRET`.

## Быстрый запуск в Windows

1. Распакуй проект в отдельную папку.
2. Дважды нажми `start.bat`. При первом запуске скрипт проверит Node.js, установит зависимости, создаст `.env` со случайным секретом и запустит сайт.
3. В браузере откроется `/start`: первый запуск ведёт на `/setup`, последующие — на `/login`.
4. На первой настройке создай аккаунт владельца курса. Затем войди и создай класс.

Скрипт `start.sh` выполняет тот же локальный запуск в Linux/macOS: `./start.sh` или `sh start.sh`.

Если запускаешь вручную, выполни в PowerShell:

```powershell
npm ci
Copy-Item .env.example .env
```

Задай в `.env` случайный `SESSION_SECRET` длиной не менее 32 символов и оставь `DATABASE_URL=` пустым для локального PGlite. Секрет можно создать так:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Затем запусти:

```powershell
npm start
```

Открой `http://localhost:3000/start`. При запуске сервер печатает адреса для устройств в локальной сети. Чтобы завершить сервер, нажми `Ctrl+C`.

## Первичная настройка и учителя

- `/setup` создаёт только первого учителя-владельца. В production запрос формы дополнительно защищён `SETUP_TOKEN`; локально первая настройка разрешена только с loopback-интерфейса.
- После создания первого учителя `/setup` отвечает 404.
- `npm run create-teacher` остаётся резервным способом создать учётную запись учителя из терминала. Если учителей ещё нет, эта запись становится владельцем.
- Пароли хранятся в виде scrypt-хеша. Временный пароль ученика показывается учителю один раз.

### Рабочее место класса

- Учитель переключается между классами и разделами кабинета; адрес страницы позволяет вернуться к выбранному классу и вкладке.
- Список учеников можно искать, фильтровать и импортировать из CSV/XLSX. При импорте сначала показывается предпросмотр; QR-код карточки входа содержит адрес страницы и логин, без пароля.
- Ученик видит задания по состоянию, возвращённые работы, близкие сроки, свой прогресс и цель недели. Личные заметки к урокам сохраняются только для вошедшего ученика.

### Задания и проверка

- Учитель создаёт задания пяти типов: собрать с нуля, исправить ошибки, дописать код, повторить по изображению-образцу и пройти короткий тест.
- К чек-листу можно добавить визуальные правила, которые проверяются в песочнице; ученик видит их в процессе работы. Учитель сохраняет критерии оценки, использует комментарии к строкам и сравнивает неизменяемые версии.
- Сроки, индивидуальный перенос, штраф за опоздание, подсказки, объявления и вопросы работают в кабинете. Сходство кода выключено по умолчанию и доступно только учителю.
- Задания и личные заметки поддерживают офлайн-черновики; при конфликте сайт предлагает выбрать версию. Запросы синхронизации повторяются после сетевых ошибок.

### Аналитика, отчёты и закрытие года

- Вкладка «Аналитика» показывает карту до 40 учеников × 40 опубликованных заданий, список учеников с пропусками/долгой неактивностью и повторяющиеся провалы автопроверок. Цвет всегда сопровождается символом и подписью; из ячейки можно открыть работу.
- Меню «Экспорт» формирует книгу Excel с листами «Журнал» и «Сроки и сдачи», формулами среднего балла, закреплёнными заголовками и русским форматом дат. CSV и JSON доступны там же.
- В профиле ученика можно скачать PDF с периодом, оценками, комментариями и графиком. Кириллический шрифт хранится локально и встроен в PDF; лицензия указана в `outputs/assets/fonts/README.md`.
- Мастер завершения года предлагает архив, перенос выбранных учеников в новый класс и выпуск. Архивные ученики продолжают входить и читать свои работы и оценки, но не могут создавать черновики или отправлять задания. Необязательное обезличивание требует явной фразы подтверждения и сохраняет оценки.
- Этапы 1–7 проверены локально на PGlite и Chromium. Финальная приёмка, результаты и список ручных проверок Render/Neon находятся в [`report/stage-7/ПРОВЕРКА.md`](report/stage-7/ПРОВЕРКА.md). Локальные значения нагрузки не заменяют проверку на production PostgreSQL. Перед публикацией пройди [DEPLOY.md](docs/DEPLOY.md), затем используй [ADMIN.md](docs/ADMIN.md).

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `NODE_ENV` | `development` локально, `production` на хостинге |
| `PORT` | Порт веб-сервера; Render передаёт его сам |
| `DATABASE_URL` | Строка PostgreSQL. Пустое значение включает локальный PGlite |
| `PGLITE_DIR` | Папка локальной базы, по умолчанию `./data/pglite` |
| `SESSION_SECRET` | Секрет HMAC-сессий, минимум 32 символа |
| `TRUST_PROXY` | `1` только когда приложение стоит за доверенным HTTPS-прокси |
| `SETUP_TOKEN` | Одноразовый ключ для создания первого учителя в production |
| `ALLOWED_ORIGINS` | Дополнительные origin через запятую; собственный origin разрешён всегда |
| `PRIVACY_CONTACT` | Публичный контакт учителя для страницы о данных; email или другой способ связи |
| `CLOUDINARY_CLOUD_NAME` | Облачное имя Cloudinary для загрузки фото профиля (необязательно) |
| `CLOUDINARY_API_KEY` | API key Cloudinary для подписанной загрузки (необязательно) |
| `CLOUDINARY_API_SECRET` | API secret Cloudinary; хранить только в переменных окружения сервера |

Образец настроек лежит в [.env.example](.env.example). Не добавляй `.env`, базу и резервные копии в Git или архив для распространения.

## Проверки и обслуживание

```powershell
npm test
npm run check:deploy
npm run check:secrets
npm run qa:browser
npm audit
npm audit --omit=dev
npm run db:check
npm run backup
npm run restore -- .\backups\имя-файла.json
```

- `npm test` запускает проверки API, доступа по ролям, лимитов для 30 учеников с одного IP, блокировки входа после перезапуска, защиты сессий, восстановления резервной копии и общих утилит кабинета. Проверки используют PGlite и работают без внешней базы.
- `npm run check:deploy` проверяет команды, файлы и локальные ссылки в инструкциях. `npm run qa:browser` открывает страницы, кабинеты, уроки и образцы проектов при ширине 1280/375 px в светлой/тёмной темах; снимки и JSON сохраняются в `report/stage-7/`.
- `npm run check:secrets` ищет известные шаблоны ключей, токенов и URL базы с паролем. Локальные `.env`, базы и резервные копии проверяются отдельными исключениями и не должны попадать в архив.
- `npm run loadtest` по умолчанию 5 минут моделирует 30 учеников с 12 автосохранениями в минуту на каждого. Результат пишет p50/p95 и ответы 429 в `report/stage-7/loadtest.json`. Это локальный замер на PGlite, не прогноз для Render/Neon.
- Редактор CodeMirror 6 и Bootstrap для урока собраны локально, поэтому примеры работают без CDN. После изменения исходников редактора выполни `npm run build:editor`, после обновления Bootstrap — `npm run build:vendor`.
- Проверки UI используют Playwright и axe-core (`axe-core` установлен только как devDependency); компонентный каталог кабинетов `/ui-kit.html` доступен в development-сборке и специально скрыт в production.
- `npm run db:check` подключается к `DATABASE_URL`, выводит версию PostgreSQL и миграции и проверяет право чтения/записи.
- `npm run backup` создаёт подписанную логическую копию JSON в `backups/`.
- `npm run restore -- файл.json` восстанавливает копию только в пустую базу. Для замены существующих данных требуется `--force` и ввод слова `ВОССТАНОВИТЬ`.
- Локальный сервер делает ежедневную копию и оставляет последние 14 ежедневных копий. Резервные копии содержат персональные данные и код работ.
- `npm run seed:demo` предназначен только для локальной демонстрации и однократно выводит тестовые пароли в терминал.

## Хостинг

Проект подготовлен для Render Web Service и внешней PostgreSQL, например Neon. Пошаговая настройка, ручные проверки и ограничения описаны в [руководстве публикации](docs/DEPLOY.md). Доступ к реальным аккаунтам Render и Neon не выполнялся.

Публичная страница [«Какие данные мы храним»](outputs/privacy.html) объясняет, что сохраняется в ученическом кабинете. Перед публикацией задай `PRIVACY_CONTACT`, согласуй место хранения со школой и проверь местные требования к данным несовершеннолетних.

## Структура

- `outputs/` — статический учебный курс и кабинеты.
- `server/` — Express API, конфигурация, PostgreSQL/PGlite, миграции и команды обслуживания.
- `test/` — автоматические проверки сервера и сценариев класса.
- `data/pglite/` — локальная рабочая база; не входит в проектный архив.
- `backups/` — локальные JSON-копии; не входят в проектный архив.
