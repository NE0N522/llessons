# Переработка кабинетов: визуальная проверка

Папки `before` и `after` содержат снимки одних и тех же экранов при ширине 1280, 768 и 375 px в светлой и тёмной темах. Имена файлов имеют формат `<экран>-<тема>-<ширина>.png`.

`before` снят с исходного коммита `a2d7dd8` в отдельном чистом worktree. `after` снят после переработки экранов кабинета. В набор входят вход, смена пароля, главная ученика, профиль, задание, каталог компонентов, выбор класса учителя, обзор класса, ученики, задания, проверка, журнал, аналитика и история. Окно проверки показано отдельно на всех трёх ширинах и в обеих темах.

Полный машинный отчёт последнего browser QA сохранён в `browser-qa.json`.

Скриншоты создаёт `scripts/stage8-account-capture.js`. Опция `--review-only` переснимает только окно проверки; `--after` сохраняет результат в `after` (без него снимки сохраняются в `before`).

Набор подтверждает визуальную компоновку и темы. Проверка реальной загрузки файла аватара в Cloudinary, живого Neon/Renders deployment и экранного диктора не выполнялась этим скриптом.

## Проверки

- `npm test`: 27/27 тестов пройдены.
- `npm run check:deploy`: 19/19 проверок пройдены.
- `npm run check:secrets`: подозрительных секретов не найдено.
- `npm run qa:browser`: 49 страниц, 196 сочетаний темы и ширины, 56 axe-аудитов, 0 нарушений и 0 ошибок.

Повторное открытие страницы задания при полностью отключённой сети этим редизайном не подтверждалось: исходный тест ждал появления редактора и завершался таймаутом. Проверки локального сохранения черновика и синхронизации после восстановления связи проходят; логику офлайн-синхронизации в рамках редизайна не менял. Для Cloudinary, опубликованного Render/Neon и реального экранного диктора нужна проверка в соответствующих средах.
