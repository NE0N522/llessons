# Этап 7 — публикация и финальная приёмка

Дата прогона: 11 ноября 2026 года. Все автоматические проверки ниже выполняются локально на PGlite и Chromium. Render, Neon, внешняя PostgreSQL и реальный школьный телефон в этой среде недоступны; их проверка оставлена владельцу в ручном списке.

### Дополнение после приёмки — автодополнение редактора

- В общем CodeMirror-редакторе `Tab` и `Enter` сначала принимают активный пункт автодополнения; `Tab` без меню по-прежнему раскрывает Emmet или добавляет отступ, `Enter` без меню переносит строку.
- Обычные HTML-атрибуты подставляются как `class=""` с курсором внутри кавычек; логические атрибуты не получают лишнее значение. CSS-свойство вставляется как `property: `; список значений расширен распространёнными цветами и размерами. Пункт меню также можно выбрать кликом.
- Сборка `npm run build:editor` завершилась успешно. Позже общий интеграционный тест редактора прошёл в полном наборе; он проверяет Emmet, редакторы заданий и режимы подсказок, но отдельные сценарии принятия именно `class=""` через Tab/Enter в список проверок не добавлялись. Версии офлайн-кэша повышены.

### Дополнение — production-база и восстановление

- Для Neon разделены endpoint-ы: `DATABASE_URL` — pooled для запросов приложения, `MIGRATIONS_DATABASE_URL` — direct без `-pooler` для схемы. Production останавливается, если direct URL не задан или ведёт на pooler. Render Blueprint запрашивает обе строки.
- Миграции выполняются в транзакциях с advisory lock на версию миграции; это защищает от параллельного старта нескольких экземпляров. `npm run db:check` применяет схему direct-подключением, затем проверяет runtime-подключение и права.
- Найденное неполное резервирование исправлено: снимок включает все 22 таблицы из миграций. Восстановление сначала создаёт родителей, затем дочерние данные, переносит связи учеников/классов и связку учебных лет, обновляет identity-последовательности и принимает старые v1-копии без новых таблиц.
- Проверки: тесты восстановления/покрытия схемы/config — 3/3; полный `npm test` — **24/24**, 204 199 мс; инструкция публикации — **19/19**. Использовалась PGlite, а не реальный Neon.

## Проверить вручную на Render и Neon

- [ ] Создать Neon PostgreSQL в регионе, разрешённом школой, скопировать pooled URL с `sslmode=require` и задать его в Render как секрет `DATABASE_URL`.
- [ ] Задать Render `SESSION_SECRET`, сгенерированный `SETUP_TOKEN`, `TRUST_PROXY=1` и публичный `PRIVACY_CONTACT`; не отправлять значения этих секретов в чат.
- [ ] Запустить `npm run db:check` локально с тем же адресом базы до публикации; после deploy проверить `/healthz` и `/readyz`.
- [ ] Открыть `/setup`, создать владельца и войти. Добавить тестовый класс и ученика, проверить вход с телефона, смену временного пароля и сохранение/отправку черновика.
- [ ] Оставить Render до сна, проверить пробуждение и повтор запроса; перед уроком открывать сайт заранее.
- [ ] Скачать резервную копию из кабинета владельца. Восстановить её только в отдельную пустую тестовую базу и сверить классы, учеников, задания и оценки.
- [ ] Распечатать карточки входа на школьном принтере; убедиться, что QR содержит логин, но не пароль, и карточки удобно разрезать.
- [ ] Проверить мобильный интерфейс в школьной сети, когда несколько учеников работают одновременно. Для нагрузочного прогона использовать staging-сервис и заранее согласованное окно.
- [ ] Согласовать с администрацией школы контакт учителя, регион/сроки хранения и публикацию страницы `/privacy.html` по требованиям страны.
