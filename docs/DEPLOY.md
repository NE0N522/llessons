# Публикация на Render и Neon

Инструкция для владельца проекта, который раньше не публиковал Node.js-приложение. Запуск в облаке не выполнялся из этой рабочей среды: шаги Render и Neon помечены для ручной проверки.

## Перед началом

- Нужен GitHub-аккаунт, Node.js 20+ на компьютере, аккаунты Render и Neon.
- Перед публикацией заполни публичный контакт учителя в переменной `PRIVACY_CONTACT`, прочитай [шаблон о данных учеников](../outputs/privacy.html) и согласуй место хранения данных со школой.
- Бесплатные тарифы и ограничения меняются. По сведениям на 11 ноября 2026 года Render Free останавливает веб-службу после 15 минут без входящих запросов, при пробуждении может потребоваться около минуты, а файловая система эфемерна. Render указывает, что бесплатные экземпляры предназначены для тестирования, а не production. У Neon отдельное хранилище и вычислитель; compute может приостанавливаться после простоя. Перед использованием несовершеннолетних сверь актуальные условия, лимиты и регион хранения на [официальной странице Render Free](https://render.com/docs/free), [странице планов Neon](https://neon.com/pricing) и [документации Neon о scale-to-zero](https://neon.com/docs/introduction/scale-to-zero). Для реальных школьных данных оцени платный тариф и требования местного законодательства.

## 1. Создай приватный репозиторий GitHub

1. На GitHub нажми **New repository**, задай имя, выбери **Private** и не добавляй README/.gitignore второй раз.
2. В папке проекта проверь, что `.env`, `data/`, `backups/` и `node_modules/` не попадут в Git. Они перечислены в `.gitignore`.
3. Если папка ещё не является Git-репозиторием, выполни в PowerShell из корня проекта:

   ```powershell
   git init
   git add .
   git status --short
   git commit -m "Подготовка учебного курса к публикации"
   git branch -M main
   git remote add origin https://github.com/ВАШ-АККАУНТ/ВАШ-ПРОЕКТ.git
   git push -u origin main
   ```

   Перед `git commit` убедись, что в staged-списке нет `.env`, файлов базы, резервных копий и `node_modules`.

## 2. Создай PostgreSQL в Neon

1. Создай проект в [консоли Neon](https://console.neon.tech/). Выбирай регион, разрешённый школой, и ближайший к Render.
2. Нажми **Connect**, выбери branch, базу и роль. Скопируй **две строки для одной базы**: с **Connection pooling** для `DATABASE_URL` и без пула для `MIGRATIONS_DATABASE_URL`. Пуленый адрес обычно содержит `-pooler`; прямой — без него. Обе строки должны включать `sslmode=require` (консоль может добавить `channel_binding=require`). Веб-приложение использует пуленый адрес, а прямой нужен для применения миграций при запуске. Neon отдельно рекомендует прямое подключение для миграций и административных операций; см. [пул соединений Neon](https://neon.com/docs/connect/connection-pooling).
3. Храни обе строки как секреты. Не вставляй их в исходники, README, чат или Git. Не удаляй пароли и SSL-параметры.

## 3. Проверь соединение до публикации

В локальном `.env` задай `DATABASE_URL` пуленой строкой и `MIGRATIONS_DATABASE_URL` прямой строкой той же Neon-базы. Добавь отдельный случайный `SESSION_SECRET` длиной не менее 32 символов. Не копируй секрет из примера. Затем в PowerShell из корня выполни:

```powershell
npm ci
npm run db:check
```

Команда применяет миграции через `MIGRATIONS_DATABASE_URL`, затем проверяет рабочее подключение `DATABASE_URL`, версию PostgreSQL и права чтения/записи. Она не выводит строки подключения. Если проверка не удалась, смотри раздел [ошибок](#если-что-то-не-работает). Для production используй отдельную Neon-базу; не проверяй восстановление на рабочей базе класса.

### Если в локальном курсе уже есть ученики или задания

Данные PGlite не попадают в GitHub или архив проекта автоматически. Чтобы перенести их, сначала выполни `npm run backup` на исходной машине и сохрани закрытый JSON-файл. Затем укажи в локальном `.env` две строки целевой Neon-базы, но оставь прежний `SESSION_SECRET` из исходной машины: им проверяется подпись резервной копии. Выполни `npm run db:check`, затем `npm run restore -- "путь-к-файлу.json"`. Neon-база должна быть пустой; восстановление заменяет данные только после отдельного подтверждения. Проверь число классов, учеников, заданий и работ. Не создавай владельца через `/setup` до переноса, иначе база уже не будет пустой. После восстановления Render использует свой сгенерированный `SESSION_SECRET`; учителям и ученикам нужно будет войти заново.

## 4. Создай Web Service из Blueprint

1. В Render открой **New → Blueprint** и подключи приватный GitHub-репозиторий.
2. Выбери репозиторий и ветку `main`, затем проверь найденный `render.yaml`.
3. Blueprint использует `npm ci`, `node server/index.js`, `/healthz`, `NODE_ENV=production` и `TRUST_PROXY=1`. Render сгенерирует `SESSION_SECRET` и `SETUP_TOKEN`; не заменяй их образцовыми значениями.
4. Для `DATABASE_URL` вставь pooled-строку Neon, а для `MIGRATIONS_DATABASE_URL` — прямую строку той же базы без `-pooler`. `ALLOWED_ORIGINS` можно оставить пустой, если используется только основной домен. Добавь дополнительный origin только если он нужен и известен.
5. Задай `PRIVACY_CONTACT`: контакт, по которому ученик или родитель сможет связаться с учителем по вопросам данных. Страница `/privacy.html` показывает его как обычный текст.
6. Подтверди Blueprint и дождись успешного deploy. Смотри **Events/Logs** Render. Секреты задаются в Render Environment, а не в `render.yaml`; это соответствует [документации Render по Blueprint](https://render.com/docs/blueprint-spec) и [переменным окружения](https://render.com/docs/configure-environment-variables).

При первом создании Blueprint Render запросит значения переменных `sync: false`. Если Blueprint уже был создан раньше, новые такие переменные добавь вручную в **Environment** сервиса и запусти новый deploy.

## 5. Первый вход и проверка

1. Открой `https://ИМЯ-СЕРВИСА.onrender.com/healthz`. Ожидается `200` и текст `ok`.
2. Открой `/readyz`. Ожидается `200` и JSON `{"ready":true}`. Этот маршрут дополнительно обращается к базе.
3. Открой `/setup`, введи сгенерированный `SETUP_TOKEN`, создай аккаунт учителя и сохрани пароль в менеджере паролей.
4. Войди через `/login.html`, создай тестовый класс, ученика и черновое задание. Проверь вход ученика и сохранение черновика.
5. Удали или замени `SETUP_TOKEN` в Render после настройки первого учителя. `/setup` и так становится недоступен после появления учителя.
6. Открой `/privacy.html` и проверь, что там отображается правильный контакт.

## 6. Свой домен (необязательно)

В Render открой настройки сервиса и добавь домен. Скопируй показанные DNS-записи к своему регистратору, дождись проверки и TLS-сертификата. Не выдумывай записи DNS: они зависят от домена и Render их показывает для конкретной службы. `TRUST_PROXY=1` должен оставаться включённым. Если сервис доступен по нескольким собственным origin, добавь их в `ALLOWED_ORIGINS` без завершающего `/`.

## 7. Подготовка к уроку и обновление

- Если выбран Render Free, открой сайт за 2–3 минуты до занятия, чтобы он успел проснуться. Экран ожидания на странице входа повторяет временно неудачный запрос, но время пробуждения не гарантировано.
- Перед обновлением скачай резервную копию из кабинета владельца или выполни `npm run backup` в настроенном окружении.
- Изменения отправляй в подключённую ветку GitHub. Render соберёт новую версию по Blueprint. После deploy проверь `/healthz`, `/readyz`, вход, одну тестовую отправку и скачивание копии.
- Если новая версия сломана, в Render открой историю **Deploys** и выбери предыдущий успешный deploy для rollback. Откат кода не откатывает миграции БД. Перед откатом проверь совместимость кода со схемой; восстановление БД делай только из проверенной копии и на подходящей базе.

## Если что-то не работает

- **`/readyz` даёт 503 или приложение не запускается на миграциях.** Проверь отдельно pooled `DATABASE_URL` и direct `MIGRATIONS_DATABASE_URL` для той же базы, правильность пароля, `sslmode=require`, сетевое соединение и права. У прямого endpoint не должно быть `-pooler`. Запусти `npm run db:check` с обеими строками.
- **Cookie не сохраняется по HTTPS.** Убедись, что `TRUST_PROXY=1`, а сайт открыт по HTTPS через Render. Не добавляй собственный `Origin` к обычному запросу.
- **Сайт долго открывается после паузы.** Дождись экрана пробуждения; не обновляй страницу много раз. Открой сайт раньше урока.
- **Ответ 429.** Подожди и повтори действие. Не запускай массовое сохранение из нескольких вкладок для одного ученика.
- **Deploy не собирается.** Проверь build log: Node должен быть версии 20+, `package-lock.json` должен совпадать с `package.json`, а build command — `npm ci`.
- **`/setup` отвечает 404.** Учитель уже создан либо не настроен `SETUP_TOKEN`. Используй обычный вход; не удаляй данные, чтобы повторно открыть setup.

## Альтернативы

Можно развернуть приложение на платном VPS с Caddy и systemd, оставив PostgreSQL внешней или установив её на отдельном защищённом сервере. Для занятий только в школе можно запускать `start.bat` на компьютере учителя и использовать частный туннель с аутентификацией; не выставляй домашний или школьный компьютер напрямую в интернет.
