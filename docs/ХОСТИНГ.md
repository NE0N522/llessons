# Локальная работа и подготовка к хостингу

## Локально

В Windows запусти `start.bat`, в Linux/macOS — `sh start.sh`. Скрипты проверяют Node.js 20+, при необходимости устанавливают npm-зависимости, создают `.env` со случайным секретом сессии и запускают сервер. Первый адрес `/start` перенаправит на `/setup`, пока не создан учитель, затем — на `/login`.

В локальном режиме приложение использует PGlite из `@electric-sql/pglite`; база находится в `data/pglite/`. Запускать можно без Render/Neon. Для участия учеников в одной школьной сети открой адрес из консоли сервера: он выводит IPv4-адрес компьютера учителя и порт.

## Размещение на Render с внешним PostgreSQL

В корне есть [render.yaml](../render.yaml) для Blueprint Web Service. Он задаёт `npm ci`, команду `node server/index.js`, проверку `/healthz`, production-режим, доверенный прокси и генерацию случайных секретов. `DATABASE_URL` и `ALLOWED_ORIGINS` Render запросит во время создания Blueprint.

Порядок настройки:

1. Создай приватный репозиторий и загрузи проект без `.env`, локальной базы, `data/` и резервных копий.
2. Создай PostgreSQL-проект в Neon. Возьми connection string с SSL и включённым пулером, если используешь рекомендованный Neon pooler.
3. Создай Render Blueprint из репозитория. В `DATABASE_URL` вставь строку подключения Neon. Сохрани сгенерированный `SETUP_TOKEN` из настроек сервиса.
4. После первого успешного deploy открой `/healthz`, затем `/readyz`. Первый проверяет доступность процесса; второй выполняет запрос к базе.
5. Открой `/setup`, создай владельца курса и проверь обычный вход через `/login`. Затем удали или замени `SETUP_TOKEN` в Render: после создания учителя он уже не нужен.
6. При HTTPS за Render-прокси оставь `TRUST_PROXY=1`. Если задаёшь `ALLOWED_ORIGINS`, укажи дополнительные origin без завершающего `/`; origin собственного сайта разрешается автоматически.
7. До первого занятия создай резервную копию и проверь её восстановление в отдельной пустой базе.

Переменные приложения: `NODE_ENV=production`, `PORT` задаёт Render, `DATABASE_URL`, `SESSION_SECRET` (минимум 32 символа), `TRUST_PROXY=1`, `SETUP_TOKEN`, при необходимости `ALLOWED_ORIGINS`.

### Ограничения бесплатных тарифов

По официальной документации Render, бесплатный Web Service засыпает после 15 минут без входящего трафика, а локальная файловая система Web Service временная. Поэтому база приложения не хранится на диске Render. Первый запрос после сна может ждать запуска сервиса; интерфейс входа показывает экран ожидания и повторяет временно неудачные запросы. [Ограничения Render Free](https://render.com/docs/free).

Neon управляет временем работы вычислителя отдельно от хранения данных и может приостанавливать compute после простоя. Условия бесплатного плана, лимиты, сроки восстановления и подключения меняются; **по сведениям на момент написания инструкции, сверь актуальные значения на официальных страницах Render и Neon перед запуском**. [Тарифы Neon](https://neon.com/pricing), [автоматическое масштабирование Neon](https://neon.com/blog/neon-autoscaling-is-generally-available).

Бесплатный тариф Render PostgreSQL имеет отдельные сроки жизни и ограничения на резервирование. В этой схеме он не используется: рабочая база — внешняя PostgreSQL, а логические копии делает приложение. Копии содержат ФИО, оценки, IP-адреса и работы учеников; храни их с ограниченным доступом. Проверь возможность скачивания и восстановления вручную после настройки базы.

## Резервные копии

- `npm run backup` делает подписанный логический JSON-дамп через подключение приложения; `pg_dump` не требуется.
- `npm run restore -- путь-к-файлу.json` восстанавливает дамп в пустую базу.
- `npm run restore -- путь-к-файлу.json --force` сначала спрашивает точное слово `ВОССТАНОВИТЬ`, затем заменяет существующие данные.
- В локальном режиме при старте создаётся ежедневная копия в `backups/`; остаются последние 14 ежедневных копий.
- В кабинете владельца есть скачивание копии. При скачивании сайт предупреждает о персональных данных.

Перед обновлением скачай резервную копию. Проверку выполняй на отдельной пустой базе, не на рабочем классе. Если потерян доступ к сервису/базе, восстанови последнюю проверенную JSON-копию через `npm run restore`.

### Необязательная копия через GitHub Actions

Если нужен отдельный расписанный `pg_dump`, настрой его самостоятельно в GitHub Actions, направляя дамп в отдельный **приватный** репозиторий резервных копий. Строку PostgreSQL храни только в GitHub Secret `DATABASE_URL`; ограничь доступ к backup-репозиторию и срок хранения артефактов. В дампе есть ФИО, логины, IP-адреса, оценки и работы учеников: не сохраняй его в публичном репозитории и не добавляй в репозиторий исходного кода. Шифруй копии перед отправкой, если выбранное хранилище не обеспечивает шифрование. Такой workflow не входит в проект и в этой среде не проверялся; сначала проверь `pg_dump` и восстановление на отдельной тестовой базе.

## Проверка внешней базы

```powershell
$env:DATABASE_URL = "вставь строку подключения Neon"
npm run db:check
```

Команда печатает версию PostgreSQL, имена применённых миграций и проверяет права таблицы `users`. В этой среде подключение к твоему Neon и создание Render Web Service не выполнялись.

## Если что-то не работает

- **Сервер сообщает про `DATABASE_URL` в production** — добавь connection string PostgreSQL в переменные Render; локально оставь `NODE_ENV=development`.
- **Сервер сообщает про `SESSION_SECRET`** — сгенерируй новый случайный секрет не короче 32 символов. Не вставляй образец из `.env.example`.
- **После сна сайт долго открывается** — дождись экрана «Сервер просыпается». Открой сайт за несколько минут до урока.
- **Cookie не устанавливается за HTTPS-прокси** — проверь `TRUST_PROXY=1` и схему HTTPS на внешнем адресе.
- **Форма получает 403** — проверь, что запрос отправлен с сайта и не добавляй вручную чужой `Origin`.
- **Получаешь 429** — подожди минуту; лимит черновиков индивидуален для ученика.
- **`/readyz` отвечает 503** — выполни `npm run db:check` локально с тем же `DATABASE_URL`; проверь SSL, права и доступность внешней базы.

Резервные варианты: платный VPS с Caddy/systemd и внешняя PostgreSQL; либо школьный компьютер в локальной сети. Не открывай порт учебного компьютера напрямую всему интернету.
