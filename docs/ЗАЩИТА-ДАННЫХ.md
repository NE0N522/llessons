# Данные учеников и защита

## Что хранится

В локальном режиме данные находятся в PostgreSQL-совместимой базе PGlite в `data/pglite/`; в production — во внешней PostgreSQL по `DATABASE_URL`. База хранит имя и логин аккаунта, парольный хеш, связь ученика с классом, задания, черновики, отправленные HTML и CSS, оценки, комментарии, прогресс и события входа. Журнал входов хранит IP и user agent до 90 дней. Сессионная cookie в браузере содержит подписанный идентификатор; в базе сохраняется запись сессии и её срок действия. Пароли и сессионные токены в открытом виде не хранятся. Email и телефоны не запрашиваются.

Учитель указывает публичный контакт для запросов о персональных данных в переменной `PRIVACY_CONTACT`. Он отображается на странице [`/privacy.html`](../outputs/privacy.html); если значение не задано, страница напоминает заполнить его до публикации.

## Доступ и защита

- Ученик видит только собственный профиль, прогресс, задания своего класса и адресованные ему работы.
- Учитель видит классы и связанные данные, созданные им; владелец курса имеет дополнительные функции управления.
- Учительский API закрыт от ученических аккаунтов; ученический API закрыт от учительских аккаунтов.
- Код ученика показывается в iframe с пустым `sandbox`, без JavaScript и без доступа к сайту-родителю. Код передаётся через `srcdoc` и ограничивается CSP; внешние ресурсы отключены.
- Сессионная cookie имеет флаги `HttpOnly` и `SameSite=Lax`; на HTTPS добавляется `Secure`. Изменяющие запросы проверяют `Origin` и JSON `Content-Type`.
- API имеет лимиты запросов; автосохранение ограничивается отдельно по ученику. Общий размер HTML и CSS черновика ограничен 200 КБ.
- Повторные неверные входы создают временную блокировку, которая хранится в базе и переживает перезапуск сервера.

## Правила преподавателя

Выдавай карточку доступа лично ученику или его родителю. Не публикуй пароли в общем чате или на доске. После создания карточки пароль нельзя посмотреть повторно; при утрате сбрось его и передай новую карточку. Не используй `npm run seed:demo` на реальных данных.

В кабинете учитель может архивировать ученика (вход блокируется, работы остаются) или безвозвратно удалить его (аккаунт, работы и прогресс каскадно удаляются). Перед удалением можно выгрузить журнал и данные класса кнопками «Экспорт CSV» и «Экспорт JSON». Проверяй выбранное действие. Удаление класса не предусмотрено: завершённый класс архивируется, чтобы сохранить историю и оценки.

## Резервное копирование и сроки хранения

Резервные копии — это копии персональных данных и кода учеников. Храни их с ограниченным доступом и шифрованием, если оно доступно. Не отправляй `data/`, `backups/`, `.env` или выгрузки работ в публичные чаты/репозитории. Установи школьный срок хранения для завершивших курс учеников, старых работ и резервных копий; приложение не удаляет старые данные автоматически. Журнал входов очищается автоматически после 90 дней.

## Ограничения

Локальный сервер рассчитан на учебный класс, а не на открытую регистрацию и публичный SaaS. Администратор компьютера управляет доступом к файлам базы и резервным копиям. HTTP в локальной сети не шифрует трафик; для внешнего доступа настрой HTTPS, обновляй зависимости, ограничь прямой доступ к Node-порту и согласуй хранение детских данных с правилами школы и местным законодательством.

Публичная страница о данных — шаблон, не юридическое заключение. Перед работой с несовершеннолетними проверь местные правила, включая разрешённую страну/регион хранения, и согласуй размещение со школой.
