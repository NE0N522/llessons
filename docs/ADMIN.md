# Руководство администратора и учителя

## Первый аккаунт учителя

При первом облачном запуске открой `/setup` и создай аккаунт владельца. После появления учителя повторно создать владельца через эту страницу нельзя. Локально резервный способ — `npm run create-teacher`; он читает `.env` и подключается к указанной базе. Пароль должен быть длиной не менее 12 символов и включать буквы и цифры.

Не делись паролем владельца. Если аккаунт учителя нужно создать на уже работающей базе, используй `npm run create-teacher` из защищённой машины, где `DATABASE_URL` задан в локальном `.env`; не вставляй URL в команду, историю терминала или этот документ.

## Ученики и пароли

- Создавай класс в панели учителя, затем добавляй учеников вручную или загружай CSV/XLSX после просмотра предпросмотра.
- Временный пароль показывается при создании/сбросе один раз. Передай карточку лично ученику или родителю. Ученик сменит пароль при первом входе, если это отмечено на карточке.
- Если пароль утерян, открой профиль ученика и выбери сброс. Старые сессии будут отозваны. Не пытайся извлечь пароль из базы: хранится только хэш.
- Для полного удаления ученика используй действие удаления с подтверждением. Оно удаляет относящиеся к аккаунту работы и прогресс; перед этим выгрузи нужные данные и проверь выбранный класс.

## Журнал входов

Учитель видит историю входов своих учеников в профиле. Сохраняются время, результат, IP-адрес и user agent. Записи автоматически удаляются после 90 дней. Ограничь доступ к профилю и выгрузкам; IP-адрес также относится к данным пользователя.

## Резервные копии

- `npm run backup` создаёт подписанную JSON-копию всех 22 таблиц в `backups/`. В кабинете владельца доступно скачивание полной копии; она включает работы, комментарии к строкам, вопросы, объявления, подсказки, историю активности и данные завершения учебного года.
- `npm run restore -- путь-к-файлу.json` восстанавливает данные только в пустую базу.
- `npm run restore -- путь-к-файлу.json --force` заменяет непустую базу только после ввода `ВОССТАНОВИТЬ`.
- Для проверки сначала создай отдельную пустую базу и восстанови копию туда. Сверь классы и количество работ. Не проводи пробное восстановление в рабочую базу.
- Храни резервные копии отдельно от Git, `.env` и публичных файлов. В JSON есть логины, ФИО, IP, оценки, комментарии и исходный код работ; ограничь доступ и удали копии по школьному сроку хранения.
- Логическая JSON-копия приложения не создаётся ежедневно на Render: его файловая система по умолчанию временная. Проверь доступный для выбранного тарифа Neon срок восстановления и выгружай отдельную копию вне Render. Neon описывает [резервные копии через `pg_dump`](https://neon.com/docs/manage/backup-pg-dump) и восстановление на новое подключение; `pg_dump` используй с прямым URL, без пулера.

Руководство по внешней Neon-базе и Render см. в [DEPLOY.md](DEPLOY.md). Автоматическая ежедневная копия создаётся только при локальном запуске; Render использует временную файловую систему, поэтому облачную базу включи в отдельный проверяемый процесс резервирования и храни копии вне сервиса.

## Обновления и миграции

Миграции лежат в `server/db/migrations/` и применяются автоматически при запуске приложения через прямое подключение `MIGRATIONS_DATABASE_URL`. Обычные запросы идут через pooled `DATABASE_URL`. Не редактируй уже применённый файл миграции; добавляй новую последовательную миграцию. Перед изменением схемы скачай копию, проверь её восстановление в отдельной БД и после deploy проверь `/readyz`.

Команда `npm run db:check` проверяет внешний PostgreSQL, версию и применённые миграции. Не запускай её на рабочем Neon, если не понимаешь значения вывода; подключение использует права, заданные в `DATABASE_URL`.

## Завершение учебного года

В классе открой действие «Закрыть учебный год». Предпросмотр показывает количество учеников, заданий и оценённых работ. До подтверждения скачай Excel-журнал и резервную копию.

- **Архив** оставляет вход ученикам для чтения работ и оценок, но запрещает новые черновики, тестовые ответы и отправки.
- **Перенос** создаёт класс следующего учебного года и переносит только выбранных учеников. История оценок остаётся связана с их прежним годом.
- **Выпуск** отключает выбранные аккаунты и завершает их сессии. Обезличивание необязательно, требует точной фразы `УДАЛИТЬ ДАННЫЕ` и сохраняет оценки и работы, удаляя личные сведения и активность.

После закрытия проверь новый класс, выпускные аккаунты и архивный вход одного тестового ученика. Подробнее о данных — на странице [privacy.html](../outputs/privacy.html) и в [документе о защите данных](ЗАЩИТА-ДАННЫХ.md).
